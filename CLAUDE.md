# CLAUDE.md

Guidance for AI agents working in this repository. Human-facing docs live in `README.md` and `docs/`; this file is
the condensed working knowledge: how to build, verify and change things without breaking the conventions.

## What this is

Ankit is an F# HTTP server that adds decks and notes to an [Anki](https://apps.ankiweb.net) collection and keeps it in
sync with an Anki sync server. It doesn't reimplement Anki: it links Anki's own Rust backend (`rslib`) through a thin
native bridge and talks to it in protobuf, the way Anki's Python and TypeScript clients do.

```
Ankit.Server (F#, Oxpecker)      HTTP API, services, background sync worker
   └── Ankit.Native (C#)         RslibBackend: typed client, P/Invoke, error decoding
         └── ankit_rslib (Rust)  C ABI over rslib, protobuf bytes in/out
               └── rslib         Anki's backend, sources restored by Paket into paket-files/
```

| Path                              | What                                                                          |
|-----------------------------------|-------------------------------------------------------------------------------|
| `src/rslib-bindings/`             | Rust crate `ankit-rslib` (cdylib) + `csharp-gen` and `header-gen` generators  |
| `src/Ankit.Native/`               | C# wrapper: `RslibBackend`, `RslibException`/`BackendException`, `Interop/`   |
| `src/Ankit.Server/`               | F# server: `Dto`, `Services`, `AnkiSyncWorker`, `Handlers`, `Auth`, `ErrorHandler`, `Program` |
| `tests/Ankit.Native.Tests/`       | xunit (C#) tests of the wrapper against a temp collection                     |
| `tests/Ankit.Server.Tests/`       | xunit (F#) tests of services, worker, and sync against a Dockerized sync server |
| `src/rslib-bindings/tests/ffi.rs` | Rust tests of the C ABI                                                       |
| `Scripts/build.fsx`               | FAKE build script, the single entry point for everything                      |
| `Scripts/gen-workflow.fsx`        | Generates `.github/workflows/main.yml` (Generaptor)                          |
| `docs/`                           | `building.md`, `server.md` (config + HTTP API), `testing.md`                  |

## Building

Prerequisites: .NET SDK 10.0 (`global.json`), Rust 1.97.1 (`src/rslib-bindings/rust-toolchain.toml`, kept equal to
Anki's), on Windows the MSVC build tools. Paket and Fantomas are local dotnet tools, restored by the `Restore` target.

Always build through the wrapper, never with ad-hoc command sequences when a target exists:

```bash
./build [options] [<target>]   # Linux / macOS / Git Bash
build.cmd [options] [<target>] # Windows (cmd or PowerShell: .\build.cmd)
```

Without a target `All` runs (Prepare, Build, Test, Test-Rslib). Options: `-c Debug|Release` (default **Release**),
`-p <jobs>` (parallel targets), `-s` (single target, no dependencies), `-f` (full clean), `--list`, `--no-logo`.

| Task                                   | Command                                   |
|----------------------------------------|-------------------------------------------|
| First time after cloning               | `./build Prepare`                         |
| Build everything                       | `./build Build`                           |
| .NET tests                             | `./build Test` (builds first)             |
| Rust tests                             | `./build Test-Rslib`                      |
| Format F# sources                      | `./build Format`                          |
| **Before every commit / push**         | `./build Before-Push`                     |
| Regenerate CI workflow                 | `./build Gen-Workflow`                    |
| Run server in Docker (port 5000)       | `./build Run`, stop with `./build Stop`   |
| Create an API key for a client         | `./build --key-name <name> New-Api-Key`   |
| Everything gone, start over            | `./build -f Clean` then `./build Prepare` |

### Generated, not committed

`Prepare` produces files that are gitignored and must exist before the solution compiles:

- `src/Ankit.Native/Generated/RslibBackend.Methods.g.cs`: one C# method per rslib backend method, with the
  `(service, method)` indices of the linked rslib. Generated by `csharp-gen` from `target/anki_descriptors.bin`.
  Never edit it; never hardcode service/method indices anywhere.
- `src/rslib-bindings/include/ankit_rslib.h`: C header from cbindgen. Nothing in the build uses it.
- `src/rslib-bindings/tools/protoc`: protoc copied from Grpc.Tools.

Rerun `./build Prepare` after changing the Anki version or the C ABI.

### Working with plain dotnet / cargo

Fine for quick iteration once `Prepare` has run:

- `dotnet build`, `dotnet test tests/Ankit.Server.Tests` work. `Ankit.Native` copies the native library from
  `src/rslib-bindings/target/{debug|release}` matching its own configuration, so for a Debug `dotnet test` run
  `cargo build` (debug) in `src/rslib-bindings` first; the Release `./build` targets use `target/release`. A missing
  library is only a build warning, and tests then fail with `DllNotFoundException`.
- `cargo build` / `cargo test` in `src/rslib-bindings` work (`.cargo/config.toml` sets `PROTOC` and
  `DESCRIPTORS_BIN`). The build script passes `--locked`; if you add a Cargo dependency, update `Cargo.lock` (e.g.
  `cargo build --offline` or without `--locked`) and commit it.
- Still finish with `./build Before-Push`: it is what CI effectively checks.

## Before committing: `Before-Push`

`./build Before-Push` = `Test` (with `Build`) + `Prepare-Sources` (Fantomas + BOM removal) + `Verify-Sources`
(`Verify-Encoding`, `Verify-Workflow`, `Verify-Format`). It does not run `Prepare`.

- The user expects `Before-Push` to pass before any commit. Run it, report the result, then commit.
- It formats before it verifies (`Format ?=> Verify-Format`, `Remove-BOM ?=> Verify-Encoding`), so formatting issues
  are fixed in place rather than failing. Review the diff afterwards: Fantomas may also reformat code near your
  changes, and those changes belong in the commit.
- Server tests include sync tests that need Docker with Linux containers; without Docker they are skipped, not failed.
  Say so when reporting results.

## CI

- `.github/workflows/main.yml` is **generated** from `Scripts/gen-workflow.fsx`. Never edit the YAML by hand: change the
  script, run `./build Gen-Workflow`, commit both. `Verify-Workflow` (part of `Before-Push` and the CI `verify` job)
  fails if they differ.
- Jobs: `Verify sources` (Ubuntu, `Verify-Sources`) and `Build and test` on `windows-2025`, `ubuntu-24.04`, `macos-15`
  (Restore → Setup-Rslib → Generate client/header → Build-Rslib → Build-Solution → Test → Test-Rslib). Cargo is cached.
  Runs on push/PR to `main`, weekly, and manually.
- The .NET SDK is pinned to `10.0.402` in `gen-workflow.fsx` because `10.0.x` resolved to `10.0.403`, which wasn't
  downloadable (HTTP 409). Switch back to `10.0.x` once that release is available.
- A full CI run takes ~15 minutes. A failure within the first minute or two is usually setup (SDK download, etc.),
  not the code: read the failing step with `gh run view <id> --log-failed` before changing anything.

## Dependencies

- **NuGet via Paket only.** Never `dotnet add package` or `<PackageReference>`. Add the package to the right group in
  `paket.dependencies` (`WebServer`, `Native`, `Test`), list it in the project's `paket.references`, and run
  `dotnet paket install` (updates `paket.lock`). Commit all three.
- **Anki version**: `group Anki` → `github ankitects/anki:<tag>` in `paket.dependencies`. After a bump: restore, keep
  `rust-toolchain.toml` equal to Anki's, `./build Prepare`, rebuild, run all tests. The sync server test image is
  built from the same tag automatically.
- **Rust**: `src/rslib-bindings/Cargo.toml`; `anki`, `anki_proto`, `anki_i18n` are path dependencies into
  `paket-files/`. The crate is its own workspace so Cargo never attaches it to Anki's.

## Architecture notes

### Native bridge (`src/rslib-bindings/src/lib.rs`)

- Every call is `(service, method, protobuf bytes) → status + AnkitBuffer`. Statuses: `ANKIT_OK`,
  `ANKIT_BACKEND_ERROR` (buffer = encoded `anki.backend.BackendError`), `ANKIT_PANIC` (panics never unwind into the
  caller: everything runs inside `guarded`), `ANKIT_INVALID_ARGUMENT`.
- Every `AnkitBuffer` handed out must be freed with `ankit_buffer_free`; `AnkitBuffer.TakeBytes()` in C# does that.
- Adding an export: write it in `lib.rs` with a `# Safety` doc section, declare it **by hand** in
  `Ankit.Native/Interop/NativeMethods.cs` (`LibraryImport`), wrap it in `RslibBackend`, add a test in
  `tests/ffi.rs` and one in `Ankit.Native.Tests`. Regenerating the header is optional.
- `ankit_translation_index` maps a Fluent key (e.g. `sync-wrong-pass`) to the indices `I18nService.TranslateString`
  needs; `RslibBackend.Translate(key, args)` uses it.

### Ankit.Native (C#)

- `RslibBackend` is a partial class: hand-written part in `RslibBackend.cs`, generated typed methods in
  `Generated/`. Calls are synchronous and thread-safe (rslib serializes access internally).
- rslib errors → `BackendException` (with `Error.Kind`); panics / bad calls → `RslibException` (its base class).
- Error messages from rslib are already localized (FTL) in the backend's language
  (`BackendInit.PreferredLangs`, `Env.defaultLangs` in the server). Don't compare against hardcoded English text; branch
  on `BackendError.Kind`, and get expected texts from `backend.Translate "<ftl-key>"` (e.g. `IErrorTextService`).

### Ankit.Server (F#)

Compile order (`Ankit.Server.fsproj`): `Utils` → `Env` → `Dto` → `Services` → `AnkiSyncWorker` → `ErrorHandler` →
`Handlers` → `Auth` → `ApiDocs` → `Program`. A new file must be added to the `.fsproj` in the right position.

- **Services** (`Services.fs`): interface + `Anki*` implementation taking `RslibBackend` (and others) by constructor,
  registered as singletons in `Program.fs`. `IErrorTextService`, `IAuthService`, `ISyncService`, `IDeckService`,
  `INoteService`, `INotetypeService`.
- **Errors are values.** Services catch only expected backend exceptions with `ServiceUtils.guardCall` /
  `guardCommand` / `guardCallSync` and return `Result`; genuine bugs propagate (`reraise ()`) to
  `ErrorHandler.errorHandler` (500). Error unions are `[<RequireQualifiedAccess>]`:
  - `InfraFail`: `BackendFailed (kind, message)` | `NativeFailed message`
  - `SyncFailed`: auth, aborted, network, server rejected, full sync required, infra (classified from `BackendError.Kind`)
  - `CommandFailed`: `NotFound` (→ 404) | `Rejected` (→ 422) | `InfraFail` (→ 500), via `CommandFailed.ofInfra`
  - Use `whenNotFound` to replace rslib's not-found text (written for the desktop app: "…use the Check Database
    action") with one naming the missing object.
- **Worker** (`AnkiSyncWorker.fs`): a `BackgroundService` reading `Channel<AnkiSyncMsg>`. It knows nothing about decks
  or notes: `AnkiSyncMsg.submit ch kind job ct` queues a `unit -> Result<_, _>` job and awaits its result. Jobs run
  one at a time; a successful `JobKind.Change` schedules a sync after `Ankit:SyncDebounceTime` ms, a successful
  `JobKind.FullSync` cancels the pending one. Writes go through the worker; reads call services directly and never
  trigger a sync.
- **Handlers** (`Handlers.fs`): `query` for reads, `change` for writes, `submit` for full sync. Bind bodies with
  `ModelBinder.bindOrDeclineJson` / `bindOrDeclineJson1` (with a route value) / `bindOrDeclineQuery`; they validate
  DataAnnotations and answer 422 with `fieldErrors`. Routes live in `Program.fs` (`routef "/notes/{%d}"` for `int64`).
- **Auth** (`Auth.fs`): API keys from `Ankit:ApiKeys` (name + `sha256:` hash, created with `./build
  --key-name <name> New-Api-Key`), checked by the `ApiKey` authentication scheme. Endpoints are public unless wrapped in
  `requireApiKey` (a route or a whole `GET [ ... ]` group), which adds the policy and the OpenAPI security
  requirement; every route except `/ping` gets it. `ApiKeyStore.load` validates the keys at startup and the server
  refuses to start without one unless `Ankit:DisableAuth` is set.
- **OpenAPI** (`ApiDocs.fs`, served at `/openapi/v1.json` via Oxpecker.OpenApi + Microsoft.AspNetCore.OpenApi;
  Swagger UI at `/swagger` from `Swashbuckle.AspNetCore.SwaggerUI`, which only serves the UI for that spec):
  every route in `Program.fs` must end with `|> describe "<OperationId>" "<summary>" <request type option>
  [ <responses> ]`, using the response values in `ApiDocs` (`ok<'T>`, `okText`, `created`, `noContent`, `notFound`,
  `invalid`, `syncFailed`, `shuttingDown`); add `|> withQuery name description` for query parameters, which can't
  be inferred. Path parameter names come from the handler's parameter names, so give `routef` a named lambda
  (`fun deckId -> ...`), not `bindOrDeclineJson1`, whose wrapper is named `x`. The generator reads ASP.NET's HTTP
  JSON options, not `jsonOptions`; `Program.fs` aligns the parts that matter (strict numbers) and schema transformers
  fix F# types: options, fieldless unions (string enums), non-option record fields (not nullable). Check the
  generated spec after adding a route or DTO.
- **DTOs** (`Dto.fs`): `[<CLIMutable>]` records with DataAnnotations (`Required`, `MinLength`, custom `NumericId`).
  JSON is camelCase (`Utils.jsonOptions`); options are skippable; fieldless unions are written as their case name in
  `SNAKE_UPPER` (`Utils.unionTagNaming`) and read case-insensitively (`"direction": "upload"` works). Conversions
  between DTOs and service types belong in `Handlers.fs`, because `Dto.fs` compiles before `Services.fs`.
- **Responses**: create → `201 {"id"}`, update/delete → `204`, reads → `200` JSON, errors → `ApiError` JSON
  (`code`, `message`, `traceId`, `timestamp`, `path`). Keep `docs/server.md` in sync when the API changes.
- Configuration: `Env.fs` (`AnkitServerSettings` section `Ankit`, `SyncServerSettings` section `SyncServer`),
  `appsettings.json`, overridable with env vars like `SyncServer__Password`. Never commit credentials.

## Code style

General (`.editorconfig`, `.gitattributes`): UTF-8 **without BOM** (`Verify-Encoding` fails otherwise), LF line
endings (`*.cmd` are CRLF), 4-space indent (2 for json/yml/xml/proj files), final newline, max line 120 (100 for Rust).

### F#

- Formatted by **Fantomas 8** with the settings in `.editorconfig` (Stroustrup brackets, records with more than one
  field go multiline, `f x` / `f ()` with a space for lowercase functions, no space for `Method()` calls). Don't fight
  it: run `./build Format`. `.fantomasignore` excludes `*.fsx` scripts and `src/Ankit.Server/Program.fs` (its route
  lists are formatted by hand).
- Idioms used throughout: `Result` + FsToolkit `result { }` computation expressions (`let!`, `do!`, `return!`),
  `[<RequireQualifiedAccess>]` unions with a companion module of the same name, `[<Interface>]` types for services,
  pipelines, `Option` instead of null at boundaries, `task { }` for async code.
- Naming: PascalCase types, union cases and members; camelCase `let` functions and values; test names are
  double-backticked sentences describing behavior (``` ``Deleted note is gone`` ```).
- Comments: few, short, and about *why* (a quirk of rslib or Oxpecker, a non-obvious decision), not *what*. `///`
  doc comments on public types and members where the meaning isn't obvious from the name.

### C#

`.editorconfig` rules: file-scoped namespaces, `using`s outside the namespace with System first, Allman braces,
`var` everywhere, expression-bodied members where single-line, collection expressions, primary constructors (see
`RslibException.cs`), `_camelCase` private fields, nullable enabled, `unsafe` + `LibraryImport` for interop. XML doc
comments (`<summary>`) on public API.

### Rust

rustfmt defaults (`cargo fmt`), one `use` per item as Anki does, doc comments on every `extern "C"` function with a
`# Safety` section, no panics across the FFI boundary.

## Testing

- `Ankit.Server.Tests`: service tests (`DeckServiceTests`, `NoteServiceTests`, `NotetypeServiceTests`) use
  `TempCollection` (fresh collection in a temp dir, disposed per test) and the helpers in `CommandAssert.fs`
  (`ok`, `notFound`, `rejected`). `AnkiSyncWorkerTests` uses a counting fake `ISyncService` and a 200 ms debounce;
  it is timing-based, so keep its margins generous. `SyncServiceTests` use `[<LinuxDockerFact>]` and an Anki sync
  server built by Testcontainers from `tests/Ankit.Server.Tests/SyncServer/Dockerfile` (first build takes minutes;
  `ANKIT_TESTS_CARGO_JOBS` limits cargo parallelism, default 4).
- `Ankit.Native.Tests` (C#, xunit) mirror that with their own `TempCollection`.
- xunit 2.9: async F# tests must return `Task` (annotate `: Task` and upcast), not `Task<unit>`.
- New behavior gets a test at the service level; verify HTTP-level behavior (routing, binding, status codes) by
  running the server (`./build Run` or `dotnet run --project src/Ankit.Server` with `Ankit__CollectionPath` pointing
  to a scratch directory) and calling the endpoints.

## Known quirks and gotchas

**rslib**

- `AddNote` with a missing or **filtered** deck silently puts the cards in the Default deck (`cardgen.rs`), which is why
  `INoteService.Add` checks the deck first. A missing notetype comes back as `InvalidInput` "missing note type".
- `RemoveDecks` / `RemoveNotes` ignore unknown ids, so the services look the object up first to answer 404.
- Deleting the Default deck (id 1) only empties it and resets its name.
- Messages contain Unicode isolation marks (U+2068/U+2069) around interpolated values when a language is set; compare
  only with text produced by the same backend.
- rslib is built with English strings only: the FTL translation submodules are missing from the Paket archive, and
  `Setup-Rslib` creates them empty.

**Oxpecker 2.1**

- Query binding is case-sensitive: query DTO fields must be lowercase to match `?query=` (see `SearchNotesDto`).
- Binding an empty query string throws inside Oxpecker; `bindOrDeclineQuery` works around it by validating an empty
  model.
- `ResponseBody` needs a body type, so a bodiless 204 is the `ApiDocs.noContent` marker, which `describe` turns into a
  real empty response.
- Nullable reference types (`<Nullable>enable</Nullable>`) are not enabled in `Ankit.Server`: in F# that switches on
  nullness checking with dozens of warnings in existing code. The nullability schema transformer covers the spec.

**Docker** (`src/Ankit.Server/Dockerfile`, used by `./build Run` / `compose.yaml`)

- Alpine images (`sdk:10.0-alpine` builds, `aspnet:10.0-alpine` runs), so the native library is built for musl in the
  image itself, through the same build-script targets CI runs. It must never come from the host.
- Grpc.Tools' `protoc` is a glibc binary: the build stage installs `gcompat` + `libstdc++` to run it.
- musl targets link the C runtime statically by default, which can't produce a `cdylib`;
  `src/rslib-bindings/.cargo/config.toml` disables `crt-static` for musl only.
- Rider's Docker "fast mode" runs the host build in the container and can't work: the host has no musl
  `libankit_rslib.so`. Use regular mode or `./build Run`.
- Alpine .NET images use invariant globalization (no ICU).
- The first build compiles rslib (several minutes); cache mounts keep cargo's registry and `target` between builds.

**Windows**

- FAKE could resolve `dotnet` to a bare `dotnet.exe` and put an empty entry at the start of `PATH`, which makes
  `cmd.exe` (MSBuild `Exec`, e.g. `dotnet paket restore`) find nothing. `dotnetCli` in `build.fsx` fixes it by using
  the script's own host; keep every `DotNet.*` call going through `dotnetCli`.
- Prefer the PowerShell tool for `build.cmd`; from Git Bash call `./build`.
- On this machine `python3` may be the Windows Store alias and hang: don't rely on Python for scripting, use F# scripts
  (`dotnet fsi`), PowerShell or POSIX tools.

## Git and PR conventions

- Commit subjects: imperative, sentence case, no prefix or trailing period (`Extract deck, note and notetype services
  from the sync worker`). The body explains *why* and any API or behavior changes, wrapped at ~72 columns.
- One logical change per commit (e.g. a build fix separate from a feature).
- Work on a feature branch and open a PR to `main` with `gh pr create`. Run `./build Before-Push` first and say in
  the PR what was tested. Call out breaking API changes explicitly in the PR description and `docs/server.md`.
- Never commit generated files (`Generated/`, `include/`, `tools/`), `packages/`, `paket-files/`, or secrets.
